01 — Problem

The unique advantage is invisible.

CWM sits on the same platform as ITSM, HR, PPM, and EAP — the same database, same identity model, same infrastructure. No external work tool has that access. But CWM doesn't use it.

Today, SPM users start every morning by hopping between siloed ServiceNow modules that don't talk to each other:

Where they goWhat they checkWhat's missing
Email / SlackOvernight escalations, messages, FYIsNo priority. No connection to sprint status.
EAPSprint board — stories in progress, blocked itemsDoesn't show ITSM incidents or PPM approvals affecting the sprint.
ITSM moduleOpen incidents assigned to themNo link to sprint context or team impact.
PPM modulePending approvalsNo visibility into which tasks are blocked waiting on these approvals.
CWMOptional. Nothing triggers them to come here first.—

All of this data lives in the same platform, the same database. But the user experiences it as five separate apps. CWM could unify this — but today it's just another stop, not the starting point.

The invisible advantageConnected Work can already pull from any ServiceNow table — a structural advantage no outside tool can replicate. But today it shows up as rows in a board column, not as intelligence. The thing that makes CWM different from Asana or Monday.com is the thing CWM doesn't surface.
Cost20+ minutes daily reconstructing context the platform already has.

03 — Solution

An AI morning briefing that reasons across every system.

Daily Pulse is an AI-generated morning briefing in CWM's My Space that reasons across every system on the Now Platform. It answers three questions, every morning:

1. What matters right now

An AI-ranked priority list with cross-system reasoning. Not "your 12 assigned items" but "these 3 matter most — here's why." Item A unblocks 2 people. Item B's dependency resolved overnight. Item C is 3x over cycle time.

2. What changed that affects your plan

An overnight diff across all boards and connected records. Not "15 items moved state" but "the blocking incident was resolved at 11pm — you can pull the API story into sprint before standup." Cross-system cause and effect.

3. What's at risk before it's too late

Predictions, not reports. "Sprint at 120% of average velocity. Team B has an unresolved dependency from Team A. This item stuck 3x normal cycle time." Early warning, not a post-mortem.

Every insight links directly to the relevant board and item. Read → tap → act.

Two surfaces, one workspaceMy Space hosts the Daily Pulse — it's why you open CWM (orientation). Team Boards are where work gets done (execution). The Pulse connects both — every insight deep-links to the board and item that needs attention.

05 — What's NOT in scope

Deliberately deferred.

ItemWhy not now
Customizable Pulse layout / widget rearrangementUsers can't configure which insights appear or reorder the briefing. Ship the default experience first, validate what users engage with, then add personalization based on usage data.
Historical Pulse archive ("what did my briefing say last Tuesday?")Useful for retrospectives, but adds storage complexity. Defer until the daily-usage habit is established.
Team-level Pulse (aggregated briefing for a manager across reports)High value for PMs and directors, but requires role-hierarchy resolution and cross-board aggregation at scale. A Phase 2 dependency — build the individual Pulse first.
Slack / Teams delivery of the PulseUsers will want the briefing in their messaging tool, not just inside CWM. Defer until the in-app experience proves value — pushing to Slack before the content is trusted risks low engagement and a hard-to-recover first impression.
Natural-language "ask the Pulse" (conversational sprint queries)Compelling but expensive — requires real-time LLM inference per query. Ship the pre-computed daily briefing first; frequent ad-hoc questions would validate the investment.
Custom alert thresholds (e.g. alert only above 130%, not 110%)Configurability adds complexity before we know what thresholds work. Ship with sensible defaults, learn from accept/dismiss patterns, then open configuration.

10 — Risks

What could go wrong.

RiskLikelihoodMitigation
AI ranking quality is poor — users ignore the PulseMediumShip with an accept/dismiss feedback loop. Measure accept rate weekly. Iterate before scaling.
Cross-system reasoning produces false positives (alert fatigue)MediumStart with high-confidence signals only (blocked, overdue). Expand gradually based on accuracy.
SPM users don't see a reason to open CWM over module-hoppingHighThe daily push notification creates the entry point. The Pulse shows cross-system value no individual module provides.
Engineering capacity split across 3 pluginsMediumP1 focuses on CWM Core + Agile. AI skills follow once the foundation is stable.
11 — Open questions

Still to resolve.

  1. Ranking approach: weighted formula (due date × blocker × dependencies × cycle time) or LLM reasoning over full context? A formula is predictable and fast; an LLM is more nuanced but slower and harder to debug.
  2. Push notification threshold: send daily regardless, or only when there are actionable insights? Always-send builds the habit, but empty Pulses erode trust.
  3. Cross-system permissions: if a PM's Pulse surfaces an ITSM incident blocking their sprint, does the PM need ITSM role access to see details — or does the Pulse show a summary without requiring source-table permissions?
  4. Scale testing: the Pulse aggregates across boards. At 2000+ connected items per user, performance is unvalidated. Needs load testing before Phase 2.
  5. Competitive moat: if Atlassian extends its Teamwork Graph to include ServiceNow data via marketplace integrations, the cross-system advantage weakens. Should CWM invest in platform-exclusive data sources (CMDB, financial plans, resource allocations) to maintain differentiation?
